MEDITEK REQUEST FORMS - COVERAGE SUMMARY
=========================================

Purpose
-------
This document summarizes every request form currently registered in
refua_tests/pages/requestForms.py and the tests that cover it.

The request-form tests open the form and simulate safe UI behavior. They do not
submit a request, create a request, or modify medical data.

Current totals
--------------
- Request forms: 6
- Common coverage groups: 6 per form
- Form-specific extra-control cases: 2
- Additional flow cases: 2
- Total collected request-form test cases: 40

Coverage monitoring checklist
-----------------------------
For each Allure/test run, monitor these columns:

| Check | Expected result |
|---|---|
| Form route | URL contains the route listed above |
| Required test ids | Every declared `data-testid` is attached |
| Visibility | Every declared control is visible |
| Interactivity | Non-submit controls are enabled |
| Valid phone | `0501234567` is retained and not invalid |
| Invalid phone | `123` produces an invalid state or visible error |
| Required content | All declared labels/text are present |
| Form-specific controls | Sick Days and Dentist controls can be interacted with |
| Allure result | Review passed/failed status per parameterized form case |

Coverage type legend
--------------------
- Navigation: opens the form from All Actions and verifies the expected route.
- Structure: verifies the page title/content and required data-testid controls.
- Visibility: verifies every declared control is visible to the user.
- Interactivity: verifies non-submit controls are enabled.
- Valid input: enters a valid phone number and verifies it remains accepted.
- Invalid input: enters an invalid phone number and verifies validation feedback.
- Content: verifies all declared form-specific text is present.
- Extra controls: interacts with controls unique to a form, without submitting.

Common tests applied to all six forms
-------------------------------------
Each form receives these six parametrized tests:

1. test_request_form_opens_from_all_actions[form]
   Type: Navigation + structure
   Checks: opens the form tile, verifies the URL, page content, and required
   data-testid controls.

2. test_request_form_required_controls_are_visible[form]
   Type: Visibility
   Checks: every required field/control and the submit button are visible.

3. test_request_form_input_controls_are_interactive[form]
   Type: Interactivity
   Checks: every non-submit control declared for the form is enabled.

4. test_request_form_required_content_is_complete[form]
   Type: Content validation
   Checks: every text requirement declared for the form is present in the page.

5. test_request_form_accepts_valid_phone_input[form]
   Type: Positive input validation
   Checks: enters the valid-format phone value 0501234567, verifies the value is
   retained, and verifies the field is not marked invalid.

6. test_request_form_rejects_invalid_phone_input[form]
   Type: Negative input validation
   Checks: enters the invalid value 123, blurs the field, and verifies that an
   aria-invalid state or visible validation error appears.

   This is an alternate entry path for the Prescription form and is counted
   under the Prescription form above.

Coverage not currently implemented
-----------------------------------
The current suite does not submit requests, so it does not yet verify:
- successful form submission
- server-side validation responses
- required-field errors caused by submitting an empty form
- field-specific error messages for every form control
- maximum/minimum length boundaries for text fields
- duplicate request behavior
- API payload correctness after submission
- cancellation or back-navigation behavior from every form
- accessibility semantics for every form control

Important status note
---------------------
The coverage cases are implemented in the TEST project. Run the suite to know
whether the current environment passes them. A test being listed here means the
coverage exists in code; it does not by itself mean the live environment passed
that case.
